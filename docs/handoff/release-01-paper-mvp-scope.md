# Release 01 PAPER MVP Scope Handoff

## 목표

1차 릴리스 목표는 실제 실거래가 아니라 `PAPER + 운영 콘솔`이다. 지금부터는 새 기능을 더 붙이는 것보다 이미 구현된 P00~P08 조각을 닫힌 루프로 연결하고 검증하는 데 집중한다.

## 고정된 포함 범위

| Phase | MVP 포함 기준 |
|---:|---|
| P00 | 도메인/API/DB 계약과 주문 상태 전이 계약 |
| P01 | SQLite 상태 저장소, 감사 로그, 알림/리스크/데이터 품질 저장 |
| P02 | 주문 의도 생성, 중복 진입 차단, `UNKNOWN` 처리, 실행 이벤트 기록 |
| P03 | 킬스위치, 복구 모드, 데이터 품질, 노출, 보호 없는 포지션 차단 |
| P04 | 실제 주문 API 없는 PAPER 잔고, 체결, 포지션, 수수료, PnL |
| P05 | 운영 상태를 확인하고 제어할 수 있는 최소 API와 정적 콘솔 |
| P06 | 마켓 선택, 캔들 파싱/upsert, stale/mismatch 상태와 리스크 연결 |
| P07 | 전략 후보 검출과 백테스트 골격. 실거래 결정에는 사용하지 않음 |
| P08 | 계좌/미체결 주문 조회 기반의 읽기 전용 복구/대조 골격 |

## 명시적으로 제외

- 실제 `LIVE` 주문 생성/취소
- 소액 실거래
- 실거래 위험 설정 변경 화면
- 장시간 WebSocket 데몬, 자동 재연결, REST 누락 캔들 보정 루프
- 실시간 차트, 고급 콘솔 화면, 전체 Playwright UI 회귀 테스트
- 이벤트 스터디, 워크포워드, 파라미터 최적화
- 자동 resume 결정, 실제 포지션 재계산, 거래소 상태 우선 복구 정책 완성

## 다음 구현 순서

1. `PAPER` 닫힌 루프를 연결한다.
   - 시장 데이터 상태를 읽는다.
   - 전략 후보를 만든다.
   - RiskManager를 통과한 주문만 PaperExecutionEngine에 전달한다.
   - 주문, 체결, 포지션, 손절 보호, 감사 로그가 저장되는지 확인한다.

2. 운영 콘솔 API를 실제 저장소 상태 중심으로 점검한다.
   - `/api/status`
   - `/api/orders`
   - `/api/positions`
   - `/api/risk/blocks`
   - `/api/data-quality`
   - `/api/alerts`
   - `/api/audit-events`

3. 업비트 키는 읽기 전용 복구/대조 확인에만 사용한다.
   - 계좌 조회
   - 미체결 주문 조회
   - 로컬 주문과 거래소 주문 상태 비교
   - 실제 주문 생성/취소 호출은 하지 않는다.

4. 검증을 우선한다.
   - `python -m pytest`
   - `python -m compileall src tests`
   - 필요하면 정적 콘솔 수동 확인 또는 Browser/Playwright 확인

## 완료 체크리스트

- [ ] `PAPER` 모드에서 실제 주문 API 호출 없이 주문/체결/포지션이 갱신된다.
- [ ] 킬스위치 ON 상태에서 신규 주문이 생성되지 않는다.
- [ ] `UNKNOWN`, `SUBMITTING`, `PARTIALLY_FILLED` 주문이 있으면 같은 마켓 신규 진입이 차단된다.
- [ ] stale 또는 mismatch 데이터 품질 상태에서 신규 진입이 차단된다.
- [ ] 보호 없는 포지션이 허용 시간을 넘기면 신규 진입이 차단되고 알림이 생긴다.
- [ ] 운영 콘솔 API에서 현재 상태, 주문, 포지션, 차단 사유, 알림, 감사 로그를 확인할 수 있다.
- [ ] 복구/대조는 읽기 전용으로 동작하며 실제 주문 생성/취소를 호출하지 않는다.
- [ ] 새 기능을 추가하지 않고 MVP 필수 범위 안에서만 남은 작업을 진행한다.

## 다음 세션 시작 지시문
