## 4. 역할별 상세 검수

### 4.1 기획자 관점

판정: 부분 적합

좋은 점:

- 1차 목표가 `PAPER + 운영 콘솔`로 명확하다.
- API와 콘솔이 최소 운영 상태를 볼 수 있게 구성되어 있다.
- 실거래 `LIVE`를 1차 범위에서 제외한 판단은 타당하다.

부족한 점:

- 실험 세션 모델이 없다.
- 페이퍼 성과 리포트가 없다.
- 전략 변경 이력과 실험 결과를 연결하는 구조가 없다.
- LIVE 승격 조건을 화면에서 판단할 수 없다.
- PAPER reset이 현금만 초기화하며, 주문/포지션/리스크 블록/실험 회차 정책이 없다.

기획 보완 우선순위:

| 우선순위 | 보완 항목 |
|---|---|
| P0 | 실험 세션 모델 |
| P0 | 페이퍼 성과 리포트 |
| P0 | 승격 게이트 화면 |
| P0 | DRY_RUN 실효성 강화 |
| P1 | 전략 보완 워크플로우 |

### 4.2 개발자 관점

판정: 부분 적합

좋은 점:

- PAPER 러너가 가상 주문/체결까지 연결되어 있다.
- 테스트가 넓게 존재하며 현재 통과한다.
- 주문 상태 전이와 감사 이벤트 기록 구조가 있다.
- 실제 주문 API 경로는 아직 열려 있지 않다.

중요 결함:

| 심각도 | 결함 | 설명 |
|---|---|---|
| P0 | 킬스위치 실시간 반영 부족 | API에서 모드를 바꿔도 실행 중인 `PaperRunner`가 최신 상태를 매 tick 읽지 않는다. |
| P0 | 복구 API 더미 흐름 | `/api/recovery/run`이 실제 `RecoveryManager`를 호출하지 않는다. |
| P0 | 리스크 지표 연결 부족 | 일손실, 노출, 연속 손절, 잔고 동기화 지표가 PAPER 실행 경로에 연결되지 않았다. |
| P0 | 원자적 저장 부족 | 주문 상태 전이, 체결, 포지션, 포트폴리오 저장이 하나의 안전한 단위로 묶이지 않았다. |
| P1 | 첫 번째 마켓만 처리 | 상위 10개 알트 실험 목적과 달리 러너가 첫 마켓 중심으로 동작한다. |

### 4.3 디자이너/UX 관점

판정: 부분 적합

좋은 점:

- 운영 감시 화면의 큰 구성은 맞다.
- 모드, 리스크, 포지션, 주문, 데이터 품질, 알림, 감사 로그가 한 화면에 있다.
- Start/Stop/Reset, Kill Switch 버튼이 있다.

부족한 점:

| 영역 | 문제 |
|---|---|
| 차단 사유 | 코드와 detail만 있어 사용자가 무엇을 해야 하는지 알기 어렵다. |
| 위험 조작 | Kill Switch, Reset, Start/Stop에 확인 모달과 결과 피드백이 부족하다. |
| 복구 진행 | 현재 단계, 실패 원인, 재개 가능 여부 화면이 없다. |
| 승격 상태 | PAPER 4주/200신호, DRY_RUN 결과, LIVE 해금 가능 여부가 없다. |
| 한국어 UX | 화면 용어가 영어 중심이라 비개발자에게 부담이 크다. |

### 4.4 퀀트/전략 검증 관점

판정: 부분 적합

좋은 점:

- FVG, OB, Trap 조합 신호의 기본 구조가 있다.
- 롱 전용 전략이라는 방향은 문서와 맞다.
- 손절/익절 시나리오를 PAPER에서 일부 검증할 수 있다.

부족한 점:

| 심각도 | 결함 | 설명 |
|---|---|---|
| P0 | Zone 상태 머신 부재 | `filled`, `invalidated`, `expired` 같은 Zone 재사용 방지 상태가 없다. |
| P0 | 캔들 확정 시점 기록 부족 | `candle_grace_ms`, 사용 가능 시각, 룩어헤드 방지 기록이 부족하다. |
| P0 | 체결 모델 왜곡 | 현재가 즉시 전량 체결에 가까워 호가, VWAP, 부분체결, 슬리피지를 충분히 반영하지 못한다. |
| P1 | 전략 실험 저널 부재 | 신호 후보, 거절 이유, 패턴 특징, 파라미터, MAE/MFE, R 성과가 저장되지 않는다. |

### 4.5 리스크/운영 안전 관점

판정: PAPER 제한 적합, LIVE 전환 부적합

좋은 점:

- 기본 모드는 `PAPER`다.
- PAPER 경로에서 실제 주문 API 호출은 차단되어 있다.
- 민감정보 마스킹 유틸이 있다.
- 미확정 주문 중복 진입 차단 구조가 있다.

부족한 점:

| 심각도 | 결함 | 설명 |
|---|---|---|
| P0 | LIVE 명시 잠금 약함 | 실제 주문 함수가 없다는 사실에 기대는 면이 있다. |
| P0 | DRY_RUN 실효성 부족 | 최소 주문금액, 호가 단위, 권한, 요청 형식 검증이 없다. |
| P0 | 복구 완료 상태 부족 | 정상 복구 후 `MATCHED`, 실패 후 `FAILED/MISMATCHED` 흐름이 약하다. |
| P1 | 페이퍼 잔고 부족 차단 부족 | 가상 현금이 음수가 될 수 있다. |
| P1 | 중앙 마스킹 보장 부족 | 유틸은 있지만 API/DB/예외 전 계층 강제는 부족하다. |

## 5. 토론 결과

### 5.1 합의된 사실

1. PAPER 자동매매 최소 골격은 있다.
2. 현재 테스트는 통과한다.
3. 그러나 장기 실험 플랫폼으로는 기록 체계가 부족하다.
4. LIVE 전환 전에는 DRY_RUN, 복구/대조, 실거래 잠금 강화가 필수다.
5. 전략 수익 신호 고도화보다 운영 안전 보완이 먼저다.

### 5.2 충돌하거나 조율이 필요한 쟁점

| 쟁점 | 의견 | 결정 |
|---|---|---|
| PAPER reset 범위 | 현금만 초기화 vs 전체 상태 초기화 | 둘 다 제공한다. `cash reset`과 `experiment reset`을 분리한다. |
| 전략 개선 우선순위 | 패턴 고도화 먼저 vs 실험 기록 먼저 | 실험 기록을 먼저 만든 뒤 패턴을 고도화한다. |
| 체결 모델 | 현재가 즉시 체결 유지 vs 호가 기반 전환 | P0에서는 비교 로그, P1에서 호가/VWAP 기반 모델로 확장한다. |
| LIVE 준비 | 주문 API 구현부터 vs 잠금/DRY_RUN부터 | 잠금과 DRY_RUN 검증을 먼저 한다. |
| 콘솔 판단 | UI가 직접 판단 vs API가 행동 목록 제공 | API가 상태별 다음 행동과 해소 조건을 내려준다. |

## 6. 타이브레이크 결정

문서의 우선순위는 다음과 같다.

```text
주문 안전성 > 리스크 차단 > 장애 복구 > 검증 가능성 > 전략 수익 신호
```

따라서 최종 우선순위는 아래처럼 정한다.

| 순위 | 개선 묶음 | 이유 |
|---:|---|---|
| 1 | 킬스위치/운영모드 실시간 반영 | 실행 중 신규 주문을 즉시 막는 기능이 최우선이다. |
| 2 | 복구/대조 실제 연결 | 재시작/불일치 상태에서 잘못된 포지션 판단을 막아야 한다. |
| 3 | DRY_RUN 실효성 강화와 LIVE 명시 잠금 | 실제 주문 전환의 안전 게이트다. |
| 4 | PAPER 리스크 지표와 상태 초기화 정책 | 실험이 왜곡되거나 막힌 채 방치되는 것을 막는다. |
| 5 | 실험 세션/전략 저널 | 전략 보완의 근거를 만든다. |
| 6 | 콘솔 UX 개선 | 비개발자가 안전하게 운영하도록 돕는다. |
| 7 | 전략 고도화와 통계 검증 | 안전하고 기록 가능한 상태에서 진행해야 의미가 있다. |
